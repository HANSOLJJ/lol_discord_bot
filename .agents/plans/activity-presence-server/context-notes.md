# 결정 기록

- 2026-09-29: `starting` 입장 대기 중(카운트다운 없음)에 일시정지하면 `paused.remaining_ms`는 `null`이다. 재개하면 입장 대기로
  돌아가고, 그때 전원이 입장해 있으면 카운트다운을 새로 시작한다(코디네이터 확정, 계약서 반영됨).
- 2026-09-29: `ready`는 계약서대로 `id` 없이 받는다. `id`가 있어도 받도록 `id` 검사보다 먼저 처리한다(코디네이터 승인).
- 2026-09-29: 입장 집합은 판과 무관하게 서버 연결 기준으로 유지한다. 새 판을 만들 때 이미 전원이 입장해 있으면 바로
  카운트다운을 시작한다(액티비티를 열어 둔 채 `start`를 누르는 흐름).
- 2026-09-29: 일시정지 때 `start_at`·`deadline`을 `None`으로 비운다. 락을 기다리던 옛 타이머가 동등 비교 guard에서 걸러진다.
- 2026-09-29: `starting` 카운트다운 중 정지는 `timeout`으로 거절하지 않는다(계약서는 advantage·picking만 규정). 타이머가 락을
  기다리던 순간이면 남은 시간을 0으로 잘라 저장하고, 재개하면 바로 시작한다.
- 2026-09-29: 정지 중에는 `me.can_pick`·`can_advantage`도 false로 둔다. 서버가 `paused`로 거절하므로 화면 버튼과 맞춘다(계약서 확장).
- 2026-09-29: 서버는 `set_present`에 `_ready_counts`(Counter)를 복사하지 않고 넘긴다. 입장 태스크와 다른 사용자의 퇴장이
  순서가 뒤바뀌어 반영되면 옛 목록이 덮어써서 나간 사람이 입장으로 남을 수 있어서, 게임이 락을 얻은 시점의 값을 읽게 했다.
- 2026-09-29: `ActivityServer`에 `heartbeat` 생성자 인자(기본 10초)를 두었다. `session_ttl`처럼 테스트에서 짧게 바꾸려는 것이다.
- 2026-09-29: 기존 테스트의 "시작 후 15초 뒤 picking" 전제는 `RulesBase.begin()`(운영: 전원 입장 + 5초, DEV: 15초)으로 바꿨다.
  서버 테스트는 대부분 DEV_MODE라 고정 자동 시작 15초를 그대로 쓴다.
